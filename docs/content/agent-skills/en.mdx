i18nkit ships two Claude Code skills, [`/i18nkit-sweep`](/i18nkit-sweep) and
[`/i18nkit-add-locale`](/i18nkit-add-locale). This page explains why they exist and installs them. Each
skill's own page documents its arguments and behaviour.

The type system covers every string that is already inside it: a catalog entry has one required property
per locale, so a missing translation cannot compile. It cannot see a hardcoded literal that never entered
a catalog, and it cannot see content that lives outside catalogs entirely - blog bodies, hero images, a
list of locale codes written out by hand. That is the blind spot, and these two skills are what covers it.

## Install the skills

The skills ship inside the published package, so `npm install @daanvandenbergh/i18nkit` already put the
targets on disk under `node_modules/@daanvandenbergh/i18nkit/skills/`. Link them into `.claude/skills/`:

```bash
mkdir -p .claude/skills
# from your project root (assumes .claude/skills/ and node_modules/ share this root):
for skill in i18nkit-sweep i18nkit-add-locale; do
    ln -s "../../node_modules/@daanvandenbergh/i18nkit/skills/$skill" ".claude/skills/$skill"
done
```

Symlinks rather than copies, because a link tracks the installed package version: `npm update` moves the
skills forward with it, and there is no copy sitting in your repo to re-sync or diff.

If your layout differs - a monorepo, a hoisted or non-standard `node_modules` - point the links at an
absolute target that node resolves for you:

```bash
pkg="$(dirname "$(node -p "require.resolve('@daanvandenbergh/i18nkit/package.json')")")"
for skill in i18nkit-sweep i18nkit-add-locale; do
    ln -s "$pkg/skills/$skill" "$(pwd)/.claude/skills/$skill"
done
```

Verify both links resolve to a real file:

```bash
ls .claude/skills/i18nkit-sweep/SKILL.md .claude/skills/i18nkit-add-locale/SKILL.md
```

Two paths printed means Claude Code will pick up both commands. Restart Claude Code so it loads them.

## Which one to run

| Skill | Use it when |
| --- | --- |
| [`/i18nkit-sweep`](/i18nkit-sweep) | You want to know which user-facing strings still bypass i18nkit. Report-only unless you pass `--fix`. |
| [`/i18nkit-add-locale`](/i18nkit-add-locale) | You are adding a language and want every catalog entry, post body, and hardcoded locale list brought with it. |

Run the sweep first when both apply. A string that never entered a catalog is invisible to the compiler,
so the add-locale worklist would skip it - sweeping first pulls those strings in, and the new locale then
lands on all of them at once.

[Adding a language](/adding-a-locale) walks the same workflow by hand if you would rather drive it
yourself.
